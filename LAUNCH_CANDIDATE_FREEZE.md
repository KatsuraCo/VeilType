## Что Входит В Кандидат

- Базовая клавиатура
  - переходы между `буквы / символы / num pad`
  - `shift / caps lock`
  - отдельный `num pad` для числовых полей
  - живая настройка высоты клавиатуры
- Шифрование и расшифровка текста
  - шифрование из клавиатуры
  - preview расшифрованного текста
  - одноразовое чтение на устройстве
  - биометрический gate там, где он включен у ключа
- Медиакапсулы
  - аудио: записать / прослушать / отправить
  - фото: снять / preview / добавить еще / отправить
  - видео: снять / preview / отправить
  - generic binary sharing для Telegram / WhatsApp и похожих целей
- Управление ключами
  - создание ключа
  - получение ключа
  - список `My keys / Saved keys`
  - редактирование существующего ключа
  - флаги `one-time`, `biometric`, `export allowed`
  - защищенный экспорт через биометрию, если она доступна
  - убран дублирующий summary-блок, оставлен один основной экран текущего ключа
- Защитные функции
  - `panic wipe`
  - cache-only хранение временных медиакапсул и shared copies
  - автоматическая зачистка временных media cache на старте приложения

## Что Осознанно Не Входит В Кандидат

- Predictive typing / подсказки
  - код частично существует, но в релиз-кандидате UX отключен
- Серверные и облачные функции
  - нет remote revoke
  - нет глобального burn-after-read
  - нет синхронизированных receipts
- Диктовка / speech-to-text
  - только отдельный demo harness
  - не интегрировано в продуктовый flow
- Интеграция TrueLock
  - не входит в этот кандидат
- Полноценный multi-photo capsule format
  - текущий формат остается однокадровым

## Ограничения Кандидата

- `RAM-only` в строгом смысле не реализован.
  Android camera/share/FileProvider поток требует реальные файлы.
  Сейчас реализован безопасный компромисс: `cache-only`, без постоянного хранения новых капсул в `filesDir`.
- Multi-photo viewer `1/5`, `2/5` не реализован как единый формат капсулы.
- Ручная проверка на реальных телефонах все еще обязательна.

## Правила Заморозки

- Во время freeze не добавлять новый продуктовый функционал, если это не исправление блокирующего бага.
- Допустимые изменения:
  - исправления падений
  - исправления сломанных сценариев
  - исправления совместимости `share / insert / permission / biometric`
  - исправления локализаций
  - UX-cleanup без изменения core-поведения
- Не добавлять во время freeze:
  - новые monetization-фичи
  - новые security-режимы
  - переделку prediction
  - диктовку
  - мост к TrueLock

## Ручной Чек-Лист Перед Product Hunt

1. Базовый набор текста
   - печать на английском
   - печать на русском
   - один тап по `shift`
   - двойной тап по `shift` -> `caps lock`
   - переключение языка
   - `num pad` в числовых полях
2. Текстовая безопасность
   - шифрование обычного текста
   - расшифровка валидного TL1
   - ошибка при неверном ключе
   - повторная блокировка после одноразового чтения
3. Аудиокапсула
   - запрос разрешения
   - автоматический старт записи после выдачи permission
   - пауза / продолжить
   - стоп
   - воспроизведение
   - отправка в Telegram
   - отправка в WhatsApp
4. Фотокапсула
   - съемка
   - preview
   - добавить еще
   - отправка
   - зачистка draft-состояния при отмене
5. Видеокапсула
   - съемка
   - стоп
   - preview
   - отправка
   - повторное открытие после отправки / отмены без мусорного состояния
6. Управление ключами
   - создание ключа
   - получение ключа
   - редактирование ключа
   - запрет экспорта
   - биометрия на экспорт
   - `panic wipe`

## Известные Зоны Риска

- Android build environment шумный:
  - Gradle / Kotlin cache иногда требует `-Pkotlin.incremental=false`
  - timeout оболочки не всегда означает провал сборки; нужно смотреть на timestamp APK
- Медиакапсулы по-прежнему рискованнее текстового сценария
- Product Hunt запуск нельзя считать готовым, пока ручной чек-лист выше не пройден на реальных устройствах
